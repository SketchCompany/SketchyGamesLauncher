# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

**Sketchy Games Launcher** — an Electron desktop app to browse the store and play indie games. It is the desktop counterpart to the web store (`SketchCompanyReact`). Shared remote backend: **`api.sketch-company.de`**. UI strings are German.

## Commands

- `npm start` (alias `npm test`) — run in dev via `electron-forge start`.
- `npm run build:renderer` — build the React SPA with Vite (→ `src/frontend-dist/`). `watch:renderer` for watch mode.
- `npm run make` (alias `build`) — platform distributables (Squirrel/Windows, DMG/macOS). `package` packages without installers. `publish` publishes to GitHub.
- `npm run lint` — no-op stub. No linter, no test suite (`test` just launches the app).
- No Electron GUI in this sandbox — verify via `npm run build:renderer` + `node --check <server file>`.

## Untracked files required to run

- **Secrets** are read from the environment at **build/publish time only** via `src/config/secrets.js` (loads `.env` through dotenv). Copy `.env.example` → `.env` (git-ignored). The packaged app bundles no secret; `forge.config.js` `ignore` keeps `.env`/legacy `src/tokens.js` out. `src/tokens.js` is deprecated.
- **`src/functions.js`** — the shared utility module — is git-ignored but **required**; a fresh clone must recreate it.
- Local data is encrypted with **AES-256-GCM**; the per-install key is managed by `src/dataKey.js` via Electron `safeStorage` (OS keychain), never shipped.
- Also git-ignored: `src/installs/`, `src/downloads/`, `src/data/`, `out/`, `src/frontend-dist/`, `.env`.
- **`src/apiBase.js`** sets two independent static headers on every call to the remote API (single choke point for `src/functions.js get/send/graphql`): `X-Launcher-Key` (`SKETCHY_LAUNCHER_KEY`, must equal the API's `LAUNCHER_SHARED_SECRET` — lets the launcher skip the Turnstile bot-check on the public auth routes only) and `X-Client-Key` (`SKETCHY_CLIENT_KEY`, must equal the API's `CLIENT_KEY_LAUNCHER` — proves to the API's global gate that *this* app is calling, required on every already-credential-gated route, unrelated to the bot-check). Both are dev-time `.env` values (`SKETCHY_*`) and, for packaged builds, obfuscated build-time modules generated by `forge.config.js` (`src/config/{launcherKey,clientKey}.js`, git-ignored). Neither is a strong secret in a distributed client — they raise the bar, they don't gate a determined reverse-engineer. See `api/API-KEYS.md`.

## Architecture

Electron does **not** load HTML over `file://`. Instead:

1. `src/index.js` (main process) boots, then `require("./launcher")` starts a **local Express server on port 1520** (falls back to 1521 if another instance answers `/api/close-for-update`).
2. The `BrowserWindow` loads `http://localhost:<PORT>/...`. The "frontend" is a **React/Vite SPA** in `src/renderer/` (built to `src/frontend-dist/`, served by Express with SPA fallback). The old `src/frontend/` jQuery app is gone.
3. On window close the app **hides to a tray** (Steam-style background) — the process + Express server keep running; real quit only via tray → "Beenden".

### Access control (User-Agent token)
`launcherConfig.requestToken` (`"SketchyGamesLauncher"`) is appended to the window's User-Agent (`index.js`). Express middleware in `launcher.js` rejects any request whose UA lacks that token, so the local server is unreachable from an external browser.

### Backend layers (Electron main process)
- `src/launcher.js` — Express app: token middleware, CSP, static assets, SPA routing, mounts the API router at `/api`.
- `src/api.js` — ~40 REST endpoints under `/api`. Proxies to the remote backend via `functions.js`. Most handlers answer `{ status: 1|0, data }`. Privileged endpoints (`games/start`/`open`/`delete`, `library/img`) resolve the product from the local `installsFile` registry via `resolveRegisteredProduct()` and enforce `isPathInside()` — plus the license check described under "Ownership" (`requireOwned`, default on). **`games/start`, `installs`, `library/img` are token-free** (work offline). Notification routes delegate to `notificationStore.js`.
- `src/downloadEngine.js` — the download/update pipeline (serial queue). **Delta mode** (default): diff the build's signed per-file manifest against the local `.sgl-manifest.json`, range-fetch only changed zip entries (inflate → sha256 → atomic rename). **Whole-zip fallback**: full zip with byte-resume, sha256, zip-slip-safe `safeExtract`. **Resume across restarts** via `downloads/<name>.state.json`. Fires a persistent "Installation abgeschlossen" notification on `finishInstall`.
- `src/functions.js` — shared utils (git-ignored, required): `fs.promises` helpers (**reject on error** — always await in try/catch), HTTP helpers (`get`/`send`/`getAndCache`), `encrypt`/`decrypt` (**AES-256-GCM**, key from `dataKey.js`), `launchProgram`/`openExternal`, `createShortcut` (Windows-only), `sendNotification` (Electron OS notification, gated on `desktopNotifications`), `checkInternetConnection` (2=internet+server, 1=internet only, 0=offline), `filterForPlatform`.
- `src/launcherConfig.js` — all paths/constants, platform-aware `appExt`, `settingsIntegrity` (+ `sanitizeSettings`), and the setup split: **`setupPaths()`** (fast local dirs/files/settings, awaited before first navigation) and **`setupBackground()`** (connectivity check, cleanup, cover repair, `checkForUpdates()`, `downloadEngine.resumeInterrupted()` — fired via `setImmediate` after the window loads). `checkForUpdates()` compares installed versions against `/v1/launcher/builds` and emits "Update verfügbar" notifications.
- `src/session.js` — session token store (`session.dat`, AES-GCM). `isSessionValid()` is a **purely local JWT-`exp` check** (no network); `getToken`/`clearSession`/`isLoggedIn`. `verifyRemote()` is the one network-touching function here — it asks `/v1/auth/session/get` whether the session still lives and is deliberately **three-valued**: `true` valid, `false` revoked (session cleared), `null` couldn't tell (offline/server error → callers must do nothing, an outage may never log anyone out).
- `src/oauthLoopback.js` — social login (GitHub/Google/Discord) via the system browser (RFC 8252 loopback): opens `/v1/auth/login/<provider>` with a `127.0.0.1:<ephemeral>/callback` redirect, captures the one-time `code`, exchanges it at `/v1/auth/oauth/exchange` for the same session JWT. Driven by `POST /api/account/oauth` (`api.js` → `finalizeSession`). No custom protocol/deep-link needed. Failures carry a stable **cause code** (`OAuthError.oauthCode`) — either from the API's `?error=<code>&provider=<p>` callback param or raised locally (`invalid_response`, `exchange_failed`, `timeout`, `cancelled`).
- `src/oauthErrors.js` — the only place holding the German OAuth failure texts. `messageFor(code, provider)` maps a cause code to a user message; anything outside the whitelist falls back to `oauth_failed`, so no foreign text from the callback URL can reach the UI. `api.js` puts the result in `{ status: 0, code, data: <text> }`; `OAuthButtons.jsx` toasts it (`access_denied` → warning, `cancelled` → silent), deferred via `lib/whenFocused.js` until the launcher window is back in the foreground — the user is still in the system browser when the failure lands, so an immediate toast would expire unseen. Contract + code table: `api/LAUNCHER-AUTH-CHANGES.md` §4a.
- `src/notificationStore.js` — process-wide **persistent** notification store (`notificationsFile`, plain JSON). `add(n,{os})` persists + optional OS notification; idempotent per `key`; `pinned` entries are non-deletable. Shared by `api.js`, `downloadEngine.js`, `index.js`.
- `src/ownership.js` — local mirror of the account's **licenses** (`data/ownership.data`, AES-GCM): `{ lastUserId, users: { <userId>: { ids, at, source } } }`. See "Ownership" below. Lazy-requires `functions`/`session`/`launcherConfig` so `partition()` stays testable outside Electron.

### Ownership (an install belongs to the account that owns it)
The installs registry is machine-global, so a second account used to see and start the first account's games. `ownership.js` mirrors `GET /v1/library` per `userId` and the **main process** does all the filtering — the renderer holds no license logic. `refresh()`/`sync()` run after every login/signup/OAuth (awaited in `finishLogin`/`finalizeSession`), in `setupBackground()` when online, on `/updates/pull`, and at most every 5 min from `enforceRemoteSession()`; `markOwned()` is called right after the license gate in `/api/download`, in `/library/add` and in `finishInstall`. `refresh()` **replaces on success only** — a failed call never empties the cache.

**Guardrail: unknown ownership ⇒ do not filter.** `ownedIds()` returns `null` when nothing is known for the current (or last) user, and `owns()` then answers `true`. An upgrade, an offline first start or a failed `/v1/library` call must never lock the rightful owner out of their own library. This is a UX/presentation gate, **not** DRM — real enforcement stays server-side (`download-url` → 403 `NO_LICENSE`).

Enforcement points: `resolveRegisteredProduct({requireOwned})` (`api.js`, the shared choke point) refuses `games/start`/`games/open` for foreign installs; `GET /installs` answers `{ games: <owned>, foreign, other }`; `/lastplayed` returns `null` for a foreign entry; `checkForUpdates()` skips foreign installs. `games/delete` and `library/img` stay open on purpose — the cleanup list ("Fremde Installationen", `components/settings/ForeignInstalls.jsx` in Settings → Downloads & Installation) must be able to show and delete them. Files are never deleted automatically. A login that switches accounts purges the previous account's `updatesFile` entries + `update:<id>` notifications; the renderer drops per-user caches via `lib/sessionEvents.js` (`sgl:session-changed` → `store.jsx`, `wishlist.jsx` re-hydrate).

**Acquiring an already-installed game** (`POST /api/download`): after the license gate, an install that is already registered is **not** downloaded again — the answer is `{ status:1, alreadyInstalled:true, updateAvailable, data:"„X" ist bereits installiert." }` and `Product.jsx` toasts it and navigates to `/library`. Because the update path uses the *same* endpoint (the "Update verfügbar" notification points at the product page), only an explicit `allowUpdate: true` — sent solely by the "Aktualisieren" button — bypasses the shortcut. `checkForUpdates()` now always writes `updatesFile` (also when empty) and `finishInstall` clears the finished entry + its notification, so the button reflects reality.

### Data & filesystem
- `globalDir` = `<userData parent>/Sketchy Games Launcher/` — shared across versions; holds `installs/` and `data/`.
- `data/` files: `installsFile`, `updatesFile`, `playtimesFile`, `notificationsFile` (**plain JSON**); `userFile`, `settingsFile`, `ownership.data` (**AES-256-GCM** via `func.encrypt`/`decrypt`); `session.dat`, `key.dat`. Always decrypt-then-`JSON.parse` for encrypted files; fall back to `settingsIntegrity` on failure. `sanitizeSettings()` normalizes settings to the known shape (unknown keys dropped, missing filled with defaults) — `/api/settings` POST **replaces** the whole file, so always send the full object.

### Login gate & Offline mode
Two local gates enforce login: the main process (`index.js`, loads `/login` unless `isSessionValid()` or a bypass) and the renderer `SessionGuard` (`lib/session.jsx`). Both are local-only so the start needs no network. Because game launch + library are token-free (a valid-but-offline session works fully) and the 10s header poll only reads the local `notificationStore`, nothing would ever surface a **server-side revoked** session — so `index.js` `enforceRemoteSession()` runs `session.verifyRemote()` twice: right after the window loads (alongside `setupBackground()`) and again whenever the window is restored from the tray. Only a definite `false` clears the session and navigates to `/login`; offline and server errors change nothing, and offline mode skips the check entirely. **Offline mode** (`offlineMode` setting): the main gate skips `/login`, `SessionGuard` skips its check, and the renderer `OfflineProvider` (`lib/offline.jsx`, `useOffline()`) disables online areas — Store/Suche/Downloads/Konto/Glocke are shown-but-disabled, online routes render `OnlineOnly` ("nur online verfügbar"), Home redirects to `/library`, and Store/Wishlist/Notifications startup fetches are skipped. Enter via the Settings toggle ("Funktionen") or the **"Offline spielen"** button on `/login`; successful login clears it. A banner in `AppShell` offers "Anmelden" to go back online.

### Leaked credentials (login gate)
The API blocks the login when the account's password turns up in a known breach (Cloudflare's leaked-credentials header plus a server-side Have-I-Been-Pwned check). `POST /v1/auth/login/email` then answers 403 with `details.code = "CREDENTIAL_LEAK"` and a short-lived recovery token instead of a session. `src/api.js` `credentialLeakResponse()` turns that into `{ status:1, data:{ credentialLeak:true, recoveryToken, verification, email } }` for both login routes; `pages/Login.jsx` switches to its `leak` step (email code for accounts without TOTP — the login's TOTP counts otherwise — plus a new password) and posts to `/api/account/credential-alert/{send-code,resolve}`. A successful `resolve` returns a normal login payload, so it runs through the same `finishLogin()` (session + `adoptAccountOwnership`). Sessions that already exist are not terminated; `AppShell` shows a banner fed by `GET /api/account/credential-alert` (checked once per start and on `sgl:session-changed`, never polled). The "Was bedeutet das?" links open `sketch-company.de/docs/sicherheit/geleakte-zugangsdaten` in the system browser via `openExternal`.

### Notification system
One model across three surfaces. `notificationStore.js` (persistent, survives restart) is the source; `api.js` routes expose it. Renderer: `NotificationItem.jsx` renders both **toasts** (`lib/notifications.jsx`, `useNotify()`) and the **bell** (`shell/NotificationsPopover.jsx`) identically, with small action buttons; `lib/notificationActions.jsx` maps declarative actions (`{kind,label,…}` — never functions) to effects. `AppShell` polls every 10s, auto-toasts new server notifications once, and shows the unread badge. OS notifications fire via `sendNotification` (also while the window is hidden in the tray).

### Error handling
`lib/api.js` `get()` throws a typed **`AppError`** (`kind` local/http/server/session) on failure; `send()` stays soft (auth flows read `status:0` themselves); `getChecked`/`sendChecked` throw on `status!==1`. `lib/loadError.js` classifies the cause (offline vs server-unreachable vs server-error, via `navigator.onLine` + the `/api/connection` probe). `components/ErrorState.jsx` is the shared fallback (cause-aware message, retry with a ≥1s spinner, retry-failure warning toast); page skeleton reloads also honor a ≥1s minimum (`lib/minDelay.js`).

### Renderer structure
`src/renderer/` — Vite + React 19 + Tailwind v4 + react-router v7. Entry `main.jsx` (provider stack: Notifications → LaunchOverlay → Offline → Store → Wishlist → Dialog), routes in `App.jsx`, shared chrome in `components/shell/AppShell.jsx`, pages in `pages/`, shared UI/skeletons/CoverImage in `components/`, contexts/helpers in `lib/`. Animations use **framer-motion** (short, `prefers-reduced-motion`-aware via `MotionConfig`; presets in `lib/motion.js`); loading uses the shimmer skeletons in `components/Skeletons.jsx`.

### News feed
`GET /api/news` proxies the API's personalized `/v1/feed`, which merges four sources into one item shape (`{ id, kind, title, body, gameId?, gameTitle?, cover?, version?, pinned, publishedAt }`): `update` (published builds for owned games + their release notes), `event`/`news` (dev posts for owned games), `announcement` (global, admin-only), `launcher` (launcher release notes). Only the launcher can know whether the running version was *just* installed — `lastSeenLauncherVersion` in the settings drives the `fresh: true` flag, and is only advanced once the matching entry actually appeared. `components/news/` holds `NewsSection.jsx` (Home, 4 items + local filter tabs), `NewsCard.jsx` (one card for every kind) and `newsKinds.js` (label/icon/accent/link target in one place — kind is always shown as icon **and** text). Full list + release notes at `/news`, `/news/launcher/:version`, `/news/game/:gameId/:version` (all `OnlineOnly`). Writing lives in the API (`apis/news.js`, `newsDatabase.ts`): devs may post for their own games only, `pinned`/global announcements/launcher notes are admin-only; patch notes are a separate editable `release_notes` table, not a column on `builds`.

### Personalised recommendations (P7)
The store row "Empfohlen für dich" is now per-user. `storeAdapter.getRecommendations` runs its own GraphQL query with its own 60 s cache — deliberately **not** the shared store cache, which holds the catalogue that is the same for everyone. `lib/recommendations.jsx` (`useRecommendations`) loads it in the renderer and clears it on `onSessionChanged`, otherwise the next account would see the previous one's rows. **Always check `personalized`**: `false` means the API returned the generic category (no session, feature off, or the user objected) — the page then keeps its own generic fallback and must not call the row "Für dich".

Events: `POST /api/events` → `/v1/events`. The `play` event is emitted from the **main process** `program.on("spawn")` handler (`src/api.js`), not the renderer — it covers all four launch buttons at once, the game is already licence-checked there, and `product.name` *is* the game id (`ownership.owns` and `addPlaytime` use it the same way). `program.on("close")` sends the session duration, which the API adds onto that day's row. `view` fires once per game id in `Product.jsx`. Nothing is ever retried: the API stores at most one row per game, kind and day.

The privacy opt-out (`GET/POST /api/account/privacy` → `/v1/account/privacy`, UI in `settings/KontoSection.jsx`) is stored **server-side on the account**, not in `launcherConfig` — it applies to the web app too, and a per-machine file would be the wrong place for a data-protection decision. Turning it off deletes the events already collected. Details: `api/RECOMMENDATIONS.md`.

### Game launch overlay
Starting a game is driven by `lib/gameActions.jsx` `play(item, event)` — the single path used by Library, Product, Home and the context menu. It opens a full-window "liquid glass" overlay (`lib/launchOverlay.jsx` provider + `components/LaunchOverlay.jsx` + `components/OrbitSpinner.jsx`) whose blur grows as a `clip-path` circle out of the clicked button (origin from the click event; `.cta-launching` keeps that button pressed + glowing). `/api/games/start` returns as soon as the process spawns, so the overlay's lifetime is driven by focus instead: `whenBlurred()` → `whenFocused()` (`lib/whenFocused.js`) — it stays until the user comes back from the game, capped at 20s with Esc/click as an escape hatch. A `status !== 1` response closes it and shows the error toast; success shows no toast. In `api.js`, `games/start` defers the `actionAfterGameStarted` hide/minimize until the overlay has been visible for `LAUNCH_ANIMATION_MS` (1s, measured from request arrival) — the game itself still spawns immediately; the delayed hide is skipped if the process already exited.

### Content filtering
Builds are platform-filtered client-side in `storeAdapter.fetchBuilds` (API `windows|mac|linux` from `process.platform`); games without a build for the platform render a disabled "Nicht verfügbar"-button. The CSP in `launcher.js` derives `img-src` from the API base (`apiBase.js`).

### Packaging (`forge.config.js`)
Squirrel (Windows) + DMG (macOS) makers; GitHub publisher (draft releases); Electron Fuses harden the build. `generateAssets` runs `vite build` before packaging. Auto-update via `update-electron-app` (polls GitHub every 5 min, **Windows-only** — macOS needs signing, currently absent); a launcher update raises a pinned notification.
